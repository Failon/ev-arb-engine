# ev-arb-engine

Офлайн MVP для исследования EV и спортивного арбитража на Python 3.12+.
Никаких реальных ставок: проект не содержит методов отправки ставок, приватных API,
скрейпинга или обхода антибот-защиты. Fixtures полностью синтетические.

## Быстрый запуск

Из каталога проекта с установленным [uv](https://docs.astral.sh/uv/):

```powershell
uv sync --extra dev
uv run ev-arb analyze fixtures/quotes.json --journal quotes.db
uv run ev-arb backtest fixtures/walk_forward.json
uv run ev-arb replay fixtures/replay.json
uv run ev-arb report fixtures/report.json
uv run pytest -q
uv run ruff check .
uv run uvicorn ev_arb_engine.api:app --host 127.0.0.1 --port 8000
```

После первоначальной установки CLI и тесты не требуют сети. Альтернатива:
`python -m pip install -e ".[dev]"`. OpenAPI доступен на `/docs`, проверка состояния
на `/health`. `POST /analyze` принимает `quotes` (массив как в fixture), `as_of`
(ISO timestamp с часовым поясом) и `budget`. Веб-сервис сам ничего не собирает.
Для CLI `--at` задаёт момент анализа; по умолчанию берётся последний received_at
fixture, поэтому пример воспроизводится независимо от даты компьютера.

## Панель исторических отчётов

После запуска uvicorn откройте `http://127.0.0.1:8000/`. Панель принимает JSON
завершённых виртуальных экспериментов, показывает итоговые показатели и график
баланса, позволяет выгрузить отчёт. Есть встроенный синтетический пример.
Внешние CDN, аккаунты и сетевые источники данных панели не нужны.

`POST /reports` и `ev-arb report fixtures/report.json` используют один формат:
`initial_balance` и массив `observations` с полями `event_id`, `settled_at`, `stake`,
`profit`, необязательным `clv`. Profit должен уже включать все расходы эксперимента.
События с датой расчёта в будущем отклоняются; на событие допускается одна строка.

ROI = суммарная прибыль / суммарный исполненный объём. Просадка вычисляется от
исторического пика баланса; одинаковые моменты расчёта агрегируются, чтобы порядок
строк не создавал фиктивных просадок. Средний CLV считается по доступным значениям,
его покрытие отражается в clv_count. Открытые обязательства и резервирование средств
не входят в график, это кривая рассчитанного P&L, а не модель доступного капитала.

95% percentile bootstrap-интервал ROI получен повторной выборкой событий с
возвращением (по умолчанию 1000 повторений, seed=42). Он предполагает независимость
и репрезентативность событий; малые выборки, корреляции и смещение отбора нарушают
эти предположения. Интервал исторического ROI не является доверительным интервалом
справедливой вероятности или гарантией будущего результата. При менее чем двух
наблюдениях интервал отсутствует. Учёт неопределённости EV в прежнем ядре остаётся
сценарным haircut, а не калиброванной вероятностной моделью.

## Реализованные шаги

1. Строгие Pydantic Event / Market / Outcome / Quote и проверка совместимости.
2. Multiplicative, additive и power devig; равновесный consensus нескольких источников.
3. Conservative EV; сканер вилок с комиссиями, доступной ликвидностью и округлением.
4. Детерминированный replay задержки, частичного исполнения и ухудшения цены.
5. Неизменяемый через интерфейс приложения журнал исходных ответов: SQLite офлайн,
   PostgreSQL через psycopg. SHA-256 канонического JSON для проверки содержимого.
6. Fair-price CLV и expanding walk-forward с purge незавершённых событий.
7. Async fixture collector и opt-in HTTP collector официального The Odds API V4.

Код разделён на небольшие модули в `src/ev_arb_engine`. Тесты проверяют каждый шаг,
включая отрицательные сценарии; сетевые ответы подменяются `httpx.MockTransport`.
`uv.lock` фиксирует зависимости.

## Совместимость рынков

Сравнение требует полного совпадения события (включая ID, команды и начало), периода,
типа, линии, упорядоченного полного набора исходов и SettlementRules. Названия команд
автоматически не склеиваются. Для будущих дополнительных провайдеров нужна явная
таблица соответствия событий. Форa задаётся относительно домашнего участника.

Поддерживаются moneyline с двумя или тремя исходами, totals и spreads с половинными
линиями. Целые и четвертные линии, возвраты, dead heat, lay и специальные условия
расчёта не поддерживаются. ruleset — явный идентификатор проверенного набора правил;
совпадение правил не определяется по похожим ценам. Модель фиксирует overtime и
abandonment; правила retirement/переноса и прочие детали должны быть закреплены
в проверенном ruleset. При неизвестных правилах collector отклоняет нормализацию.

## Математика и ограничения

- Decimal odds `d`, комиссия с выигрыша `c`: `d_eff = 1 + (d - 1)*(1 - c)`.
  Это модель комиссии на отдельный выигравший исход, не расчёт комиссии биржи
  по совокупной прибыли рынка. Все суммы в одной условной валюте.
- Devig: нормировка `1/d`; additive вычитает равную долю маржи и отклоняет
  невалидные вероятности; power численно решает `sum((1/d)^k)=1`.
- Consensus усредняет devig вероятности минимум двух разных reference sources,
  исключая оцениваемый источник. Анализ выбирает последний доступный snapshot
  каждого источника с возрастом не более 30 секунд. Независимость источников
  не гарантируется: коррелированные копии линий нужно исключать вручную.
- Conservative EV: `max(0, p - haircut)*d_eff - 1 - cost`. Haircut по умолчанию
  2 процентных пункта — сценарное допущение, не статистический доверительный интервал.
- Вилка: выбирается лучшая effective price каждого исхода, размер ограничивается
  бюджетом и ликвидностью; ставки округляются вниз до 0.01. После округления заново
  считается минимальная прибыль всех исходов и вычитается fixed cost.
  Это простой сканер: он не оптимизирует комбинации площадок ради максимальной ёмкости.
- `simulate` использует только snapshots, полученные к моменту arrival, ограничивает
  каждую ногу доступной ликвидностью, применяет fill_fraction и adverse_move.
  Если нога отсутствует или устарела, её исполнение нулевое; открытый риск отражается
  в `pnl_by_outcome`. Ликвидность — объём для одного плана, без общего пула между планами.
  Это воспроизводимый stress scenario, не оценённая на реальных данных модель исполнения.
- `clv(taken, closing_probability) = d_eff * p_close - 1`: знак сравнения с fair close.
  Closing probability передаётся исследователем из совместимого pre-match close;
  replay автоматически выбирает closing snapshots из переданной истории.
  Загрузки closing line из внешнего API пока нет. CLV не равен реализованной прибыли.
- Walk-forward получает заранее записанные ResearchTrade: predicted_ev фиксируется
  при решении, net_return — только после settled_at. Порог выбирается по средней
  доходности обучающих сделок среди 0%, 2%, 5%, далее оценивается следующий интервал.
  Train допускает только settled_at < начало fold; один trade на event; test интервалы
  не пересекаются. Незавершённые сделки учитываются отдельно и не входят в ROI.
  Нельзя передавать признаки, рассчитанные с использованием будущих данных:
  движок проверяет временные границы, но не происхождение сторонних признаков.
  Команда backtest проверяет готовые записи; replay строит эти записи из котировок.
  Малый синтетический пример не доказывает прибыльность.

## Исторический replay

`ev-arb replay fixtures/replay.json` и `POST /replay` принимают один формат:
`events`, `boundaries` и опциональный `config`. Каждый элемент events содержит
историю совместимых `quotes`, моменты `decided_at`, `closing_at`, `settled_at`
и рассчитанный по правилам рынка `winner`. Явный null означает void; неизвестные
результаты в этот формат не передаются. Победитель не вычисляется из счёта автоматически.

На событие допускается одно решение. В момент решения выбирается исход с максимальным
conservative EV среди доступных полных снимков минимум трёх источников. При равенстве
используется стабильная сортировка source/outcome. При arrival применяется последняя
доступная цена выбранного источника, его ликвидность, fill_fraction и adverse_move;
неисполненные сделки отмечаются отдельно. Это сценарий исполнения по цене arrival,
без лимитной защиты от ухудшения цены. Запоздавшее старое наблюдение не заменяет свежее.

CLV строится по двум или более свежим reference sources на closing_at, исключая
источник сделки. Если closing snapshots отсутствуют, CLV равен null с явным статусом.
История после cutoff не влияет на решение или исполнение. Результаты содержат
фактический объём, прибыль, CLV, ResearchTrade и walk-forward folds. Суммарная profit
масштабируется на исполненные объёмы; walk-forward ROI использует unit returns.
Это два разных показателя, они подписаны отдельно. ReplayConfig фиксирован до
walk-forward; подбирать его по всей тестовой истории нельзя.

## Разрешённый внешний API

Адаптер реализован по [официальной документации The Odds API V4](https://the-odds-api.com/liveapi/guides/v4/).
Он использует только GET `/v4/sports/{sport}/odds/`, h2h, decimal odds и явный API key.
Низкоуровневое подключение выполняется из Python после проверки условий подписки,
правил букмекеров и разрешённого использования данных. Для ограниченного сбора
через CLI теперь доступен отдельный live-пилот, описанный ниже.

```python
import httpx
from ev_arb_engine.collectors import TheOddsAPICollector
from ev_arb_engine.journal import Journal

# Внутри async-функции; api_key берётся из окружения, audited_rules из вашей конфигурации.
async with httpx.AsyncClient() as client:
    with Journal("quotes.db") as journal:
        collector = TheOddsAPICollector(
            client, api_key, "tennis_atp_example", audited_rules, journal
        )
        quotes = await collector.collect()
```

Используйте действительный sport key из API вместо example. На каждый bookmaker key
нужны явные SettlementRules. API не гарантирует объём исполнения: liquidity по умолчанию
0, поэтому live-данные без отдельного обоснованного допущения не создают вилок.
Raw JSON записывается до нормализации; ключ и URL с секретом в журнал не попадают.
Timeout 20 секунд, редиректы и автоматические повторы выключены; 429 возвращается
как ошибка без повторных запросов. Никогда не включайте HTTP debug-логи с API key.

$env:POSTGRES_PASSWORD = "replace-with-local-password"
docker compose up -d
$env:TEST_POSTGRES_DSN = "postgresql://researcher:replace-with-local-password@localhost:5432/ev_arb"

Для CLI передайте DSN в `--journal` вместо SQLite пути. Таблица raw_quotes создаётся
автоматически; исходные payload не перезаписываются и повторные наблюдения сохраняются.

пропускается, если TEST_POSTGRES_DSN не задан, и добавляет одну тестовую запись.

## Диагностика расхождения источников (+EV)

`analyze` / `POST /analyze` дополнительно возвращают для каждого исхода:
`reference_count`, `reference_probability_min`, `reference_probability_max`,
`min_reference_conservative_ev` и `references_agree_on_positive_ev`.
Это независимые от прежних полей **диагностические данные**, а не новый
автоматический критерий принятия решения. Для целевого букмекера используются
только другие источники с доступными на момент анализа снимками; вероятность
каждого эталона вычисляется отдельно методом power devig.

`references_agree_on_positive_ev` истинно, если **каждый** доступный эталон
даёт строго положительный сценарный EV после того же haircut, что и основной
расчёт. Отрицательный или нулевой минимум не скрывается средним consensus.

Важно: источники могут копировать линии друг друга, поэтому число эталонов
не равно числу независимых оценок. Разброс между ними **не** является
доверительным интервалом, а haircut в 2 процентных пункта **не** был
статистически калиброван. Оценку качества сигналов следует проводить
на хронологическом holdout: калибровка вероятностей (Brier/log loss),
CLV с независимой закрывающей линией, доля доступных closing snapshots,
симуляция исполнения с частичными fill и net ROI на завершённых сделках.

## Автономный research scanner и виртуальный счёт

```bash
uv run ev-arb scan-demo fixtures/quotes.json --ledger paper.db
```

Команда делает один воспроизводимый синтетический проход, показывает сигналы,
состояние источника и виртуальный счёт. Повторный запуск с той же БД не открывает
вторую сделку на событие. Никаких внешних запросов или сообщений Telegram.

`Scanner.run(iterations=..., interval=60, on_batch=...)` выполняет ограниченную
последовательность асинхронных проходов. `Scanner.tick()` выбирает время после
сбора, а `tick(at)` воспроизводит фиксированный исторический cutoff. Нет look-ahead:
будущие received_at и observed_at исключаются. Каждый полностью совместимый рынок
анализируется отдельно; +EV требует трёх разных исходных букмекеров, теоретическая
вилка может использовать двух. Два reseller-канала одного букмекера должны быть
сведены к одному ID через `AuditedCollector` перед передачей сканеру.

Для живого источника нужен `synthetic=False` и только `AuditedCollector` с проверенными
маппингами событий и букмекеров. Это программный интерфейс для будущего подключения:
реальная интеграция пока не проверена и не включена в CLI. Перед использованием
нужны разрешённая подписка, проверенные ответы и правила хранения данных. Лимит
`FeedSlot.requests_per_hour` задаётся явно (по умолчанию 60); при общем API key
квоту необходимо делить между слотами. После ошибки — backoff 60–3600 секунд;
429 Odds-API.io приостанавливает сбор минимум на час и дольше по Retry-After.
Квоты/backoff хранятся в памяти; процесс один, перезапуск не должен обходить лимиты.
Здоровые источники продолжают работу при сбое соседнего; тексты исключений скрыты.

`PaperLedger` сохраняет SQLite-счёт и резерв открытых позиций; доступный капитал
не может расходоваться повторно. Допускается одна EV-сделка на событие. Нулевая
ликвидность не создаёт исполнения. Fill fraction и adverse move — явно заданные
сценарии мгновенного исполнения, комиссия берётся из effective odds; задержки и CLV
по историческим снимкам проверяются отдельным `replay`. Вилки пока только сигналы,
их исполнение в этом счёте не моделируется. Расчёт сделки требует явного известного
исхода и времени после начала события; null означает void. Повторный одинаковый
расчёт ничего не меняет, противоречащий расчёт отклоняется. Автоматического
получения результатов нет. Это модель paper trading, не доказательство доходности.

## Telegram: синтетическое демо уведомлений

```bash
# Только локальный просмотр: токен и сеть не нужны
uv run ev-arb alerts-demo fixtures/quotes.json
```

`alerts-demo` по умолчанию возвращает текст трёх синтетических уведомлений.
Уведомления по реальным источникам программно отключены: проверка разрешённого
живого доступа и прав передачи котировок из #5 ещё не завершена. Не подавайте в
демо реальные или конфиденциальные данные, оно предназначено только для fixtures.

Для самостоятельного запуска именно синтетических сообщений:

1. Создайте бота через официальный @BotFather (`/newbot`), сохраните токен локально
   в `TELEGRAM_BOT_TOKEN`; не отправляйте его в чат, GitHub или журналы.
2. Откройте личный чат с ботом и отправьте `/start`. Получите собственный числовой
   chat ID из `message.chat.id` официального `getUpdates` в локальном клиенте,
   задайте `TELEGRAM_CHAT_ID`. Не используйте сторонних ботов для передачи токена.
3. Запустите `uv run ev-arb alerts-demo fixtures/quotes.json --send --state alerts.db
   --iterations 10` одной строкой. Флаг `--send` явно включает настоящие сообщения
   о синтетическом примере. В этой проверке такие сообщения не отправлялись.

В режиме отправки пример переносит синтетические timestamps к текущему времени,
сохраняя возраст котировок и фиксированное начало события. Проходы раз в 60 секунд,
отдельный polling команд раз в 2 секунды, 1–100 проходов; Ctrl+C останавливает процесс.
Запускайте один экземпляр на bot token/chat/state DB. Не используйте webhook
одновременно с polling. Для сервера храните env в secrets сервиса, SQLite на
постоянном локальном диске, HTTP debug-логи выключите: URL Bot API содержит токен.
Не удаляйте state DB для обхода cooldown или квоты. Параметры бота для Python-клиента
задаёт `TelegramConfig`: пороги EV/прибыли, свежесть, спорт/рынок, timezone,
cooldown, существенное изменение и максимум уведомлений в час.

Поддерживаются `/start`, `/help`, `/status`, `/pause`, `/resume`; остальные чаты
не получают ответа и не меняют состояние. `/pause` останавливает новые уведомления;
уже отправленный запрос отозвать нельзя. Состояние pause, polling cursor,
дедупликация и лимит уведомлений сохраняются в SQLite. Ключ дедупликации включает
событие, полный рынок, исход и источник; fingerprint учитывает снимки эталонов.
Повторный fingerprint не отправляется, новый снимок внутри cooldown допускается
только при достаточном изменении EV или моделируемой прибыли. По умолчанию
cooldown 300 секунд, material change 0.01, максимум 20 уведомлений в час.

Очередь ограничена, при переполнении новые сообщения пропускаются; сбой Telegram
не останавливает сканирование. После 429 возможен один повтор по retry_after,
если ожидание не превышает 30 секунд и котировки останутся свежими. Длинный
retry_after блокирует следующие запросы без ожидания в сборщике. Ошибки сети
и неоднозначный результат отправки не повторяются автоматически; exactly-once
доставка не гарантируется при сбое процесса между отправкой и записью состояния.
Никакие HTTP-тексты ошибок и секреты не включаются в ответы приложения.

Сообщение содержит paper/synthetic label, спорт, событие, время с часовым поясом,
рынок и правила расчёта, цены и комиссии, observed/received/возраст, число эталонов,
оценку fair probability и conservative EV либо теоретическую худшую прибыль,
допущение о ликвидности и предупреждение о необходимости проверки цены/правил.
Проверка перед отправкой повторно отсеивает устаревшие/несовместимые снимки и
неподтверждённые значения EV. Источник API: https://core.telegram.org/bots/api;
регистрация бота: https://core.telegram.org/bots/features#botfather.

## OddsPapi + The Odds API: бесплатный пилот на реальных котировках

Добавлены `live-check`, `live-discover`, `live-run`, `live-report` и конфигурация
`config/free-trial.json`. Пилот ограничен тремя днями, сохраняет исходные ответы,
инвентаризацию БК, сигналы и расход квоты между перезапусками. Без ключей сетевых
запросов нет. Сначала discovery и проверка рынков/правил, затем реальные сигналы;
пустая конфигурация собирает данные, не придумывая совместимость букмекеров.
Полная инструкция: [docs/free-feed-trial.md](docs/free-feed-trial.md).

```bash
uv run ev-arb live-check
uv run ev-arb live-discover --config config/free-trial.json
uv run ev-arb live-run --config config/free-trial.json
uv run ev-arb live-report
```

Авторизация обоих API и первые живые ответы проверены; трёхдневный сбор начат
17 ноября 2026. Подтверждённых EV-сигналов ещё нет: проверка bookmaker settlement
